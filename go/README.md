# eventreduce (Go)

Go implementation of the [EventReduce algorithm](https://github.com/pubkey/event-reduce).
It takes the previous results of a query and a change event of the database
and calculates the new results **in memory, without running the query over the database again**.

It uses the BDD that the [JavaScript implementation](../javascript/) created,
so both always decide on the same action. It needs Go 1.22 or newer and has no dependencies.

## Usage

```go
import eventreduce "github.com/pubkey/event-reduce/go"

type User struct {
	ID  string
	Age int
}

// SELECT * FROM users WHERE age > 18 ORDER BY age, id LIMIT 10
queryParams := eventreduce.QueryParams[User]{
	GetDocumentID: func(u User) string { return u.ID },
	Limit:         eventreduce.Int(10),
	QueryMatcher:  func(u User) bool { return u.Age > 18 },
	// must never return 0 for two different documents,
	// so sort by the primary key last
	SortComparator: func(a, b User) int {
		if a.Age != b.Age {
			return a.Age - b.Age
		}
		return strings.Compare(a.ID, b.ID)
	},
	// true if one of the sort fields differs between the two versions of a document
	SortFieldsChanged: func(previous, doc User) bool { return previous.Age != doc.Age },
}

results := []User{{ID: "a", Age: 20}, {ID: "b", Age: 30}}

// a change event from the change stream of your database
changeEvent := eventreduce.InsertEvent("c", User{ID: "c", Age: 25})

action := eventreduce.CalculateActionName(&eventreduce.StateResolveFunctionInput[User]{
	QueryParams:     queryParams,
	ChangeEvent:     changeEvent,
	PreviousResults: results,
})
if action == eventreduce.RunFullQueryAgain {
	results = runQueryOnDatabase() // EventReduce could not optimize this event
} else {
	results, _ = eventreduce.RunAction(action, queryParams, changeEvent, results, nil)
	// -> [a, c, b]
}
```

`Skip` and `Limit` are pointers, nil means none, `eventreduce.Int()` creates them.
`ChangeEvent.HasDoc()` and `ChangeEvent.HasPrevious()` tell if `Doc` and `Previous` are set,
they are not set on deletes and inserts.

### Key document map

For big result sets, pass a map from the id to the document as `KeyDocumentMap`
to `CalculateActionName()` and as the last argument of `RunAction()`.
It is used to check whether a document is in the results without scanning them,
and `RunAction()` keeps it in sync with the results.

### Differences to the JavaScript implementation

- Change events are created with `InsertEvent()`, `UpdateEvent()` and `DeleteEvent()`.
- Instead of `primaryKey` and `sortFields`, the `QueryParams` take `GetDocumentID`
  and `SortFieldsChanged`, so documents can be any Go type.
- `RunAction()` returns the new results, like `append()`, and an error instead of throwing:
  `ErrRunFullQueryAgain` and `ErrUnknownAction`.
  `AlwaysWrong` is only used by the truth-table generator and returns `ErrUnknownAction`.

## Result window buffer

For a query with a limit or a skip, EventReduce returns `RunFullQueryAgain` when a row has to move into the result window that is not in the previous results:
the row after the window (when a row leaves a full window) or the last skipped row (when a row is added in front of the window).
The result window buffer avoids most of these full queries: it keeps `limitBufferSize` rows after the window and `skipBufferSize` skipped rows before it in memory.
It works like the [result window buffer of the JavaScript implementation](../docs/result-window-buffer.md),
which explains how it works, how to choose the buffer sizes and has measurements.

```go
// recommended size: about log2(limit), at most 30
size := eventreduce.GetRecommendedResultWindowBufferSize(queryParams.Limit)
buffer, _ := eventreduce.NewResultWindowBuffer(queryParams, size, size)
// run the query with the skip and limit of the buffer
buffer.Reset(runQuery(buffer.Query()))
// the rows of the original skip and limit
results, _ := buffer.Results()

// on new change events
result := buffer.ApplyChangeEvents(changeEvents)
if result.RunFullQueryAgain {
	buffer.Reset(runQuery(buffer.Query()))
	results, _ = buffer.Results()
} else if result.Changed {
	results = result.Results
}
```

`Query()` returns the `Skip` and `Limit` to run the query with, `Limit` is nil if all rows after the skip are needed.
`ResultWindowBufferAllRows` as a buffer size keeps all rows on that side.
`ApplyChangeEvents()` compares the rows with `reflect.DeepEqual` to find out if the results changed.

## Development

```sh
go test ./...
gofmt -l . && go vet ./...
```

The BDD is generated by the truth-table generator of the JavaScript implementation,
which also writes `bdd_generated.go`. The tests run the [shared test suite](../test-suite/), the same tests as all other implementations.
