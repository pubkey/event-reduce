# event-reduce (Kotlin)

Kotlin implementation of the [EventReduce algorithm](https://github.com/pubkey/event-reduce).
It takes the previous results of a query and a change event of the database
and calculates the new results **in memory, without running the query over the database again**.

It uses the same binary decision diagram as the [JavaScript implementation](../javascript/),
so both always decide on the same action.
The library only uses the Kotlin standard library, so it works on the JVM and on Android.

## Installation

The library is on Maven Central, use the version of the [latest release](https://github.com/pubkey/event-reduce/releases):

```kotlin
dependencies {
    implementation("dev.rxdb:event-reduce:<version>")
}
```

## Usage

```kotlin
import dev.rxdb.eventreduce.*

data class User(val id: String, val age: Int)

// SELECT * FROM users WHERE age > 18 ORDER BY age, id LIMIT 10
val queryParams = QueryParams<User>(
    getDocumentId = { it.id },
    limit = 10,
    queryMatcher = { it.age > 18 },
    // must never return 0 for two different documents,
    // so sort by the primary key last
    sortComparator = compareBy<User> { it.age }.thenBy { it.id },
    // true if one of the sort fields differs between the two versions of a document
    sortFieldsChanged = { previous, doc -> previous.age != doc.age },
)

var results = mutableListOf(User("a", 20), User("b", 30))

// a change event from the change stream of your database
val changeEvent = ChangeEvent.Insert("c", User("c", 25))

val action = calculateActionName(StateResolveFunctionInput(queryParams, changeEvent, results))
if (action == ActionName.RunFullQueryAgain) {
    results = runQueryOnDatabase() // EventReduce could not optimize this event
} else {
    runAction(action, queryParams, changeEvent, results)
    // -> [a, c, b]
}
```

### Key document map

For big result sets, pass a `MutableMap` from the id to the document as `keyDocumentMap`
to both `calculateActionName()` and `runAction()`.
It is used to check whether a document is in the results without scanning them,
and `runAction()` keeps it in sync with the results.

### Differences to the JavaScript implementation

- Change events are the sealed classes `ChangeEvent.Insert`, `ChangeEvent.Update` and `ChangeEvent.Delete`.
- Instead of `primaryKey` and `sortFields`, the `QueryParams` take `getDocumentId`
  and `sortFieldsChanged`, so documents can be any Kotlin class.
- `sortComparator` is a `Comparator`.
- `ActionName`, `StateName` and `ResultWindowBufferResult` are enums, `jsName` returns the name used by JavaScript.
- `runAction()` throws an `EventReduceException` for `RunFullQueryAgain` and `UnknownAction`.
  `AlwaysWrong` is only used by the truth-table generator and throws like `UnknownAction`.

## Result window buffer

For a query with a limit or a skip, EventReduce returns `RunFullQueryAgain` when a row has to move into the result window that is not in the previous results:
the row after the window (when a row leaves a full window) or the last skipped row (when a row is added in front of the window).
The result window buffer avoids most of these full queries: it keeps `limitBufferSize` rows after the window and `skipBufferSize` skipped rows before it in memory.
It works like the [result window buffer of the JavaScript implementation](../docs/result-window-buffer.md),
which explains how it works, how to choose the buffer sizes and has measurements.

```kotlin
// recommended size: about log2(limit), at most 30
val size = getRecommendedResultWindowBufferSize(queryParams.limit)
val resultWindowBuffer = createResultWindowBuffer(queryParams, limitBufferSize = size, skipBufferSize = size)
// run the query with the skip and limit of the buffer
resetResultWindowBuffer(resultWindowBuffer, runQuery(getResultWindowBufferQuery(resultWindowBuffer)))
// the rows of the original skip and limit
var results = getResultWindowBufferResults(resultWindowBuffer)

// on new change events
when (val result = applyChangeEventsToResultWindowBuffer(resultWindowBuffer, changeEvents)) {
    is ResultWindowBufferChangeResult.RunFullQueryAgain -> {
        resetResultWindowBuffer(resultWindowBuffer, runQuery(getResultWindowBufferQuery(resultWindowBuffer)))
        results = getResultWindowBufferResults(resultWindowBuffer)
    }
    is ResultWindowBufferChangeResult.Results -> if (result.changed) results = result.results
}
```

`getResultWindowBufferQuery()` returns the `skip` and `limit` to run the query with, `limit` is null if all rows after the skip are needed.
`RESULT_WINDOW_BUFFER_ALL_ROWS` as a buffer size keeps all rows on that side.

## Development

```sh
./gradlew test
```

The BDD is generated by the truth-table generator of the JavaScript implementation,
which also writes `BddGenerated.kt`. The tests run the [shared test suite](../test-suite/), the same tests as all other implementations.
