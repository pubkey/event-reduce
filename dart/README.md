# event_reduce (Dart)

Dart implementation of the [EventReduce algorithm](https://github.com/pubkey/event-reduce).
It takes the previous results of a query and a change event of the database
and calculates the new results **in memory, without running the query over the database again**.

It uses the same binary decision diagram as the [JavaScript implementation](../javascript/),
so both always decide on the same action. Works with Flutter and plain Dart.

## Usage

```yaml
dependencies:
  event_reduce:
    git:
      url: https://github.com/pubkey/event-reduce
      path: dart
```

```dart
import 'package:event_reduce/event_reduce.dart';

class User {
  final String id;
  final int age;
  const User(this.id, this.age);
}

// SELECT * FROM users WHERE age > 18 ORDER BY age, id LIMIT 10
final queryParams = QueryParams<User>(
  getDocumentId: (doc) => doc.id,
  limit: 10,
  queryMatcher: (doc) => doc.age > 18,
  // must never return 0 for two different documents,
  // so sort by the primary key last
  sortComparator: (a, b) {
    final byAge = a.age.compareTo(b.age);
    return byAge != 0 ? byAge : a.id.compareTo(b.id);
  },
  // true if one of the sort fields differs between the two versions of a document
  sortFieldsChanged: (previous, doc) => previous.age != doc.age,
);

var results = [User('a', 20), User('b', 30)];

// a change event from the change stream of your database
const changeEvent = ChangeEvent<User>.insert(id: 'c', doc: User('c', 25));

final action = calculateActionName(StateResolveFunctionInput(
  queryParams: queryParams,
  changeEvent: changeEvent,
  previousResults: results,
));

if (action == ActionName.runFullQueryAgain) {
  results = await runQueryOnDatabase(); // EventReduce could not optimize this event
} else {
  results = runAction(action, queryParams, changeEvent, results);
  // -> [a, c, b]
}
```

The full example is in [example/example.dart](./example/example.dart).

### Key document map

For big result sets, pass a `Map` from the id to the document as `keyDocumentMap`
to both `calculateActionName()` and `runAction()`.
It is used to check whether a document is in the results without scanning them,
and `runAction()` keeps it in sync with the results.

### Differences to the JavaScript implementation

- Change events are created with `ChangeEvent.insert()`, `ChangeEvent.update()` and `ChangeEvent.delete()`.
- Instead of `primaryKey` and `sortFields`, the `QueryParams` take `getDocumentId`
  and `sortFieldsChanged`, so documents can be any Dart class.
- `ActionName` and `StateName` are enums.
- `alwaysWrong` is only used by the truth-table generator and throws like `unknownAction`.

## Development

```sh
dart pub get
dart test
```

The BDD is generated by the truth-table generator of the JavaScript implementation,
which also writes `lib/src/bdd_generated.dart`. A test ensures that both implementations use the same BDD.
